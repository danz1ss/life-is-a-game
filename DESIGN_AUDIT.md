# Аудит продукта, UX и текущего UI

4 октября 2026. Основа: [PRODUCT.md](PRODUCT.md), весь активный frontend `src`, функции состояния и реальный renderer приложения. Направление — [DESIGN.md](DESIGN.md).

**Результат пользовательского просмотра первой концепции.** Пользователь предпочитает существующие карточки и две круглые отметки; идея убрать крестик в меню отозвана. Герой справа с уровнем понравился, но текущие монеты должны быть рядом и сразу видимы. Серые мелкие подписи и главная цель оказались незаметными; главный квест недостаточно выделен, edit/delete отсутствовали. Это прямое свидетельство о восприятии, более важное для выбора иерархии, чем формально прошедший contrast check. Golden Screen версии 2 исправляет эти пункты; исходные снимки и измерения ниже остаются исторической базой. Первоначальный ориентир на недельные задачи с подзадачами позднее уточнён до простого чек-листа, описанного в версии 4.

**Отзыв о версии 2 и корректировка версии 3.** Пользователь просит общую доску под задачами, одну рамку для героя с вехой, выразительную и читаемую типографику и выравнивание уровня/монет. Назначение времени через полную форму долгое; пользователь выбрал drag на часовую шкалу. Версия 3 реализует эти группировки, локальный Golos Text и смысловые цвета, одинаковые строки метрик, drag задач на 15-минутные позиции, перенос по шкале и возврат в «В любое время». Дополнительный точный ввод не требует Modal. Риск: desktop drag не равен native touch и должен иметь клавиатурную альтернативу; в прототипе она есть через выбор задачи и inline time. Недельная модель и сохранения остаются вне этой функции прототипа.

**Отзыв о версии 3 и корректировка версии 4.** Пользователь оценивает результат положительно и просит вынести main из доски: общая рамка с двумя половинами, собственные рамки дневного фокуса и недельных задач. Main компактный, выполнение только в плане дня; сами карточки должны сильнее выделяться. Недельный сценарий уточнён: 3–5 простых названий/чекбоксов без дат и времени, Пн–Вс, воскресное вечернее ревью и новый план. Версия 4 реализует эти правки в Golden Screen, усиливает поверхности/границы карточек и размещает действия рядом с названием. Недельные результаты и будущий план независимы, правка сохраняет чекбокс, удаления обратимы, XP/монеты не меняются. См. [weekly-verification.json](artifacts/design-phase1/weekly-verification.json). Production schema и постоянное хранение этой новой сущности требуют интеграции, прототип живёт в памяти.

**Предыдущая версия 5: точный drag и восстановление обзора навыков.** Пользователь просит левый ⋮⋮, grab/grabbing, небольшой подъём, отчётливую линию вставки, плавный drop и немедленное сохранение. Название сразу после кружка, меню справа. Эти требования реализованы поверх общего QuestCard; в той версии крестик оставался быстрым вторичным действием справа. Порядок макета сохраняется в отдельном ключе browser storage, кроме него состояние остаётся в памяти. По дополнительному запросу герой был расширен/уплотнён и размещён рядом с заголовком Сегодня; под ним все восемь навыков с настоящими уровнями/XP. На 1366×768 тот обзор заканчивался около y665. [reorder-verification.json](artifacts/design-phase1/reorder-verification.json) проверяет 15 групп взаимодействий, включая мышь, клавиатуру, Chromium touch input, edge scroll, invalid storage, reload и сохранность чужих данных. Физический touchscreen и production migration этим не объявляются проверенными.

**Отзыв о версии 5 и корректировка версии 6.** Пользователь уточняет пару отметок и возвращает крупный вертикальный образ: первая строка **⋮⋮ → ✓ → × → название → …**, оба кружка рядом слева перед названием. Герой на ноутбуке занимает рамку 380×596 px со сценой высотой 280 px; уровень 32 px/700, монеты 28 px/650 с иконкой 16 px на общей высоте. Крупный герой принят последним отзывом; обзор «Мои навыки» размещён непосредственно под ним справа в отдельной рамке без счётчика. Он показывает конечные навыки без дочерних направлений: fixture — Спорт, Сон, Чтение, Английский и Программирование. Родительские категории и все связи остаются в дереве. Широкий обзор имеет три колонки при содержимом ≥580 px, две по умолчанию и одну при ≤290 px; полные названия не обрезаются. Требование уместить все восемь навыков в первый viewport заменено доступностью конечных навыков под героем справа. [Предыдущая версия 6](artifacts/design-phase1/golden-v6-morning-1366.png) проверена на четырёх ширинах: 22 дневных, 10 недельных и 15 drag-групп, ошибок браузера нет, измеренный контраст ключевых текстовых ролей ≥6,95:1. Перестановка сохраняет scoped ID-порядок; AppState/SQLite/AppData не меняются.

**Отзыв о версии 6 и корректировка версии 7.** Пользователь просит шире рамки героя/навыков, аккуратнее отступы и подсветку кнопок. На 1366×768 герой теперь 440×614,30 px, навыки 440×376 px; принятая вертикальная сцена 280 px сохранена. Обзор остаётся непосредственно под героем, без счётчика, с пятью конечными навыками. Inset 20 px, header gap 18 px, row padding 12/14 px, gaps 8/24 px; название 15 px/600, иконка 20 px, XP 13 px/500, шкала 4 px. Последний нечётный элемент двухколоночного списка занимает весь ряд, поэтому название «Программирование» помещается целиком. При содержимом ≤360 px список одноколоночный, при ≥580 px трёхколоночный. Текстовые tertiary actions остаются прозрачными при hover, ярче и подчёркнуты (offset 4 px), keyboard focus — кольцо 2 px; primary/secondary сохранены. При ≤1100 px композиция становится одноколоночной для читаемости плана, при 1101–1200 px правая колонка 400 px; фокус дня/недели остаётся парой половин от 641 px и складывается при ≤640 px. Девять состояний на четырёх ширинах, 22 дневных и 10 недельных групп прошли без browser errors; главный фокус около 207,78 px высотой, длинные названия/пять недельных задач проверены, TypeScript прошёл. 15 drag-групп относятся к предыдущей проверке версии 6; новый прогон версии 7 этим не заявляется. Scoped сохранение порядка и изоляция AppState/SQLite/AppData сохранены. [Текущий макет](http://127.0.0.1:5190/artifacts/design-phase1/golden/index.html?v=7).

**Уточнение процента большой цели в версии 7.** Вопрос пользователя о «40%» показал двусмысленность связи с главным квестом дня. Подпись уточнена до «Готовность 40%», tooltip объясняет ручную оценку большой цели; её детали показывают «Готовность большой цели» / «40% · ручная оценка». Процент остаётся свойством долгосрочной цели, не пересчитывается автоматически при выборе, удалении или выполнении дневного квеста. Это пояснение существующего правила, без изменения модели или начислений.

Точечная QA версии 7: текстовые actions прозрачны в rest/hover/active/focus, hover ярче и подчёркнут, настоящий Tab показывает кольцо 2 px с offset 2 px без clipping/transform. Mouse/Enter открывают диалог, Escape закрывает и возвращает focus. Вся область навыка, включая шкалу 4 px, кликабельна; progressbar остаётся доступным отдельным элементом. Ошибок браузера нет, измеренный контраст ключевых текстовых ролей ≥6,95:1.

## Метод и границы

Историческое уточнение версии 6: крупный герой принят пользователем; обзор навыков должен занять свободную область сразу под героем в правой колонке. Промежуточное расположение под дневным планом заменено. Справа навыки идут в две колонки; три колонки остаются возможностью компонента при ширине содержимого ≥580 px. Это уточнение расположения не меняет навыки, награды или сохранения.

Приложение запущено через Vite, интерфейс проверен Chromium на Windows. Данные для проверки созданы в изолированном browser context: герой уровня 4 (590 XP, 18 монет), цель на 40%, три задачи сегодня и одна завтра. Это демонстрационные данные, не личное сохранение. Первая загрузка проверена отдельно.

Обязательные размеры: 375×900, 768×900, 1440×900 для Сегодня, Квестов, Дерева и Прогресса; дополнительно 1366×768 для рабочего ноутбука. Golden Screen проверен при 375×812 и 768×1024. Описание исходных размеров — [current-ui-measurements.json](artifacts/design-phase1/current-ui-measurements.json). В ширинах 375/768 проверяется renderer, а не существующая поддержка мобильного Electron: окно приложения имеет минимум 1040×700.

Просмотрены App/main, четыре страницы, активные UI-компоненты и все CSS-поверхности. Проверены формы, дерево и детали навыка, гардероб и закрытые варианты, путь развития, магазин, покупка, использование приобретённой награды, уровень, отметки, ревью, настройки тем, данные, loading и ошибка загрузки. Код сопоставлен с моделью version 5, планами, completion/undo, highestLevel, stateSaver, validation и SQLite bridge.

Полная проверка установленного Electron, реального импорта/экспорта личного сохранения, NVDA, touch и экранной клавиатуры не выполнена. Запуск Electron с отдельным профилем для снимка был предпринят, но скрытое окно не дало завершённого захвата; его вывод не используется как доказательство визуального качества. Browser-проверка и штатные unit tests завершены. Существующие пользовательские изменения в репозитории не откатывались.

## Продуктовая карта

| Система | Факт текущего продукта | Дизайн-следствие |
| --- | --- | --- |
| Назначение | Личная CRM саморазвития, общий взгляд + действия | Сохранить цель и связь с навыком, не свести Home к списку галочек |
| Core loop | Цель → квест → отметка → XP/монеты → рост | Одна ведущая операция и конкретный результат рядом |
| Progression | totalXp, уровни героя/навыков, unlocks | Рост отображает активность, не объективное мастерство |
| Задачи | Разовые/повторяющиеся, даты, время, трудность, main по дате, порядок, архив | Не менять recurrence или переносы ради новой раскладки |
| Цели | SkillGoal с purpose, criteria, ручным %, active/paused/completed | Не вычислять % из XP; все активные/приостановленные цели доступны |
| Отметки | completedDates, skippedDates; без отметки — отдельная ситуация | Отдельный нейтральный статус, без чувства поражения |
| Герой | Пол/кожа/волосы/outfit/weapon/accent; этапы 1/10/25/50/75/100 | Разделить сохранённый выбор и фактически поддержанное изображение |
| Питомцы | fox/owl/dragon по уровню; petName и общая стадия роста | Показать спутника и следующий этап; не добавлять уход |
| Награды | Монеты за задачу/уровень, личные gifts, магазин, purchasedRewards | Разные условия получения и использования |
| Достижения | LevelBadges выводит каждые 5 уровней, но не подключён | Предложить отображение существующих вех, не новую механику |
| Коллекция | Купленные награды до использования; options внешности производные | Нет отдельного persisted collection/rarity/new/read schema |
| Статистика | Home top skills, XP, activeDays, history | Progress сейчас без активных графиков; старые CSS-классы не функция |
| Сохранение | Локальная SQLite в Electron, browser fallback localStorage, backup JSON | Понятный save status; ошибка чтения не заменяет данные новой игрой |
| Навигация | Local page state today/quests/tree/progress; tomorrow ведёт к planner | Сохранить topology и entry points, не добавлять router без причины |

Утро/день/вечер подтверждены пользователем. Тест 3–5 секунд — проектный критерий: текущая визуальная композиция мешает быстро заметить долгосрочную цель и ближайшую награду. Это экспертное наблюдение; замера на выборке пользователей нет.

## Классификация элементов

PRESERVE — работающий принцип/поведение; RESTYLE — визуальный язык; IMPROVE — usability/hierarchy; REDESIGN — композиция; REMOVE — лишняя визуальная подача, не данные и не функция.

| Элемент | Решение | Причина / следующая работа |
| --- | --- | --- |
| Четыре основных пункта nav | PRESERVE + RESTYLE | Компактная понятная topology; убрать отдельную рамку каждого пункта |
| Save status, local data и backup flow | PRESERVE | Надёжность и контроль пользователя |
| Общая тёмная основа / кириллический font | PRESERVE | Соответствует Calm/Trustworthy; обновление шрифта не требуется |
| Greeting большого размера | REMOVE | Заменить повторяющееся приветствие функциональным «Сегодня» |
| Home layout | REDESIGN | Цели далеко внизу, герой мал, закрытие дня впереди действий |
| Главный квест | PRESERVE + IMPROVE | Приоритет на дату работает; вложенный inset контейнер убрать |
| Duplicate main в списке | PRESERVE | Один объект с двумя представлениями; нельзя дважды начислить XP |
| Главные цели | IMPROVE | Поднять смысл цели; остальные цели оставить доступными |
| План сегодня / tomorrow | PRESERVE + RESTYLE | Сохранить привычные QuestCard и все действия; усилить читабельность |
| Список / расписание | PRESERVE | Timeline имеет полезное время и длительность |
| Две круглые отметки | PRESERVE | Пользователь подтвердил ✓ / × в быстром доступе; улучшить видимость выбранного состояния и подписи |
| Reorder quest | IMPROVE | Добавить управление без drag |
| Close-day | IMPROVE | Спокойный итог ниже действий + ясные последствия |
| Требует решений / архив / повторения | PRESERVE | Неотмеченное и невыполненное не уничтожаются |

| CharacterStage геометрия | PRESERVE | Единое пространство героя и питомца уже решает взаимное положение |
| Масштаб героя на Home | IMPROVE | 66×66 слишком мало для эмоционального якоря |
| Большой hero в Progress | REDESIGN | Сцена растягивает верх страницы и отодвигает unlocks |
| Wardrobe / portrait mapping | IMPROVE функционально + RESTYLE | Сохранённый outfit не влияет на PNG |
| Pets | PRESERVE + IMPROVE | Рост/вид/имя уже есть; явно показать вход и условие |
| Путь развития | IMPROVE | Ближайшая веха прежде длинного общего пути |
| Личные gifts за уровень | PRESERVE + IMPROVE | Вывести из менее очевидного пути развития, уточнить label |
| Магазин и bought inventory | PRESERVE + RESTYLE | Покупка и использование работают; разные группы |
| LevelBadges | IMPROVE / предложение подключения | Компонент есть, активного экрана достижений нет |
| Top skills | PRESERVE + RESTYLE | Показывает распределение активности; не заменять фальшивым графиком |
| Ui.Modal / формы | IMPROVE | Единая клавиатура, фокус и scroll; новая библиотека не нужна |
| Appearance themes | PRESERVE + IMPROVE | Выбор пользователя сохраняется; hero фиксированного navy нарушает согласованность |

## Существенные UX-проблемы и предложения

Приоритет P1 — влияет на основную работу или достоверность; P2 — следующий этап качества. Ниже у каждого изменения явно выделены Problem → Evidence → Proposed change → Benefit → Risk.

### UX-01 · P1 · Цель теряется в композиции

**Problem:** дневной план воспринимается отдельно от долгосрочного результата. **Evidence:** в [today-1440.png](artifacts/design-phase1/today-1440.png) заголовок целей начинается примерно на y=823, содержимое ниже fold; в [today-1366.png](artifacts/design-phase1/today-1366.png) блок не попадает в первую область чтения. `DashboardPage.tsx:120` помещает его после сводки навыков. **Proposed change:** контекст активной цели перед главным квестом; все остальные цели оставить отдельным доступным списком/входом. **Benefit:** видна связь намерения и действия. **Risk:** одиночный goal context может скрыть другие направления; миграция обязана сохранить доступ ко всем активным и приостановленным целям.

### UX-02 · P1 · Ведущие действия конкурируют

**Problem:** «Новый квест» ярче основной отметки, а закрытие дня стоит перед задачами. **Evidence:** [today-1440.png](artifacts/design-phase1/today-1440.png), `DashboardPage.tsx:94`. Нулевое число отметок уже вызывает большую amber review bar. **Proposed change (уточнено пользователем):** create вторичен; выполнение только через привычные ✓ / × в плане, без дублирующего CTA в фокусе; ревью ниже плана с понятным пояснением последствий. **Benefit:** днём проще продолжить работу, вечером найти итог. **Risk:** итог станет менее заметным; оставить явную постоянную кнопку и проверить вечерний сценарий. Не вводить автоматическое закрытие по времени.

### UX-03 · P1 · Гардероб обещает неподтверждённый результат

**Problem:** смена outfit не меняет изображение. **Evidence:** [outfit-changed-art-unchanged-1366.png](artifacts/design-phase1/outfit-changed-art-unchanged-1366.png), [extra-evidence.json](artifacts/design-phase1/extra-evidence.json): `outfitArtUnchanged=true`, label «Куртка путника». `CharacterPortrait.tsx:19` выбирает PNG по gender/stage/crystal, без outfit. Некоторые hair варианты и skin также не имеют полноценных независимых assets. **Proposed change:** asset coverage matrix, честный preview, затем mapping сохранённых IDs на поддержанные изображения/слои. **Benefit:** пользователь видит действительно сохранённый образ. **Risk:** значительный объём арт-работы; нельзя молча удалить выбранные IDs или сгенерировать несовместимые варианты.

### UX-04 · P1 · Фокус выходит из Modal

**Problem:** клавиатурный пользователь оказывается в фоне диалога. **Evidence:** `Ui.tsx:14`, `extra-evidence.json:dialogFocusEscapes=true`; Escape работает, autofocus формы работает, но общая модалка не удерживает/возвращает фокус. AppearanceModal имеет собственное частичное решение. **Proposed change:** исправить shared Modal: trap, inert, restoration, stacked dialog handling. **Benefit:** все формы получают одно предсказуемое поведение. **Risk:** вложенная личная награда внутри roadmap; тестировать верхнюю модалку и восстановление её инициатора.

### UX-05 · P2 · Рост героя и следующий unlock плохо связаны

**Problem:** Home показывает маленький портрет и счётчики, без конкретной ближайшей вехи; Progress уводит награды вниз. **Evidence:** stage 66×66 на Home; в [progress-1440.png](artifacts/design-phase1/progress-1440.png) сцена занимает большую секцию примерно y299–863. **Proposed change:** конечная высота сцены, один XP progress, рядом реальный ближайший unlock и его условие. **Benefit:** квест ощущается шагом личного пути. **Risk:** увеличенный герой может вытеснить задачи; уменьшать сцену по высоте ноутбука раньше рабочего контента.

### UX-06 · P2 · Узкий renderer обрезан

**Problem:** essential actions уходят вправо и недоступны обычным скроллом. **Evidence:** [today-375.png](artifacts/design-phase1/today-375.png), [quests-768.png](artifacts/design-phase1/quests-768.png), measurements: root/document 1000 px; `styles.css:62` min-width/overflow. **Proposed change:** адаптировать композицию и primitive dialogs; затем отдельно рассмотреть минимум Electron. **Benefit:** небольшие окна и будущий узкий просмотр работают без clipping. **Risk:** текущий shipped desktop minimum 1040; мобильная поддержка не должна отвлечь от утреннего ноутбука. Это renderer debt, не заявленная критическая поломка уже поддержанного телефона.

### UX-07 · Уточнено пользователем · Сохранить две круглые отметки

**Problem:** первая концепция убрала знакомую пару ✓ / × и edit/delete, поэтому список стал менее полезным. **Evidence:** прямой отзыв пользователя: «мне логика с двумя круглишками больше нравится» и запрос вернуть редактирование/удаление. **Proposed change:** сохранить исходные QuestCard/QuestActions, две круглые кнопки и выбранные состояния, добавить читаемую подпись результата; edit/delete и восстановление работают в версии 2. **Benefit:** привычные быстрые отметки и полный цикл управления задачей. **Risk:** название/pressed должно читаться в контексте конкретной карточки; обеспечить видимый keyboard focus. Предыдущее предложение перенести skip в меню отозвано.

### UX-08 · P2 · Разные награды скрыты под общим путём

**Problem:** уровень, личное поощрение, покупки и экипировка воспринимаются одной большой системой. **Evidence:** [roadmap-1440.png](artifacts/design-phase1/roadmap-1440.png), [shop-1440.png](artifacts/design-phase1/shop-1440.png), [collected-reward-1440.png](artifacts/design-phase1/collected-reward-1440.png). Gifts находятся внутри roadmap; label «Личные цели по уровням» конфликтует с целями навыков. **Proposed change:** понятные группы «Подарки за уровни», «Личные награды», «Куплено»; wardrobe/pets отдельно в Прогрессе. **Benefit:** известно, что открывается автоматически, покупается или требует получения. **Risk:** не добавлять новый верхний route и не менять useImmediately/claimed logic.

### UX-09 · P2 · Все горизонты выглядят как шкалы

**Problem:** прогресс задачи, цели, навыка, героя не всегда различим по смыслу. **Evidence:** Home повторяет bars в hero, skills, goals; цель показывает % из отдельной ручной модели. `Ui.tsx:4` не предоставляет progress semantics; runtime count progressbar=0. **Proposed change:** день — счётчик; текущий квест — статус; XP — шкала; цель — ручной % с критерием; долгий путь — вехи. **Benefit:** понятно, что измеряет каждый показатель. **Risk:** сохранённые goal progress нельзя пересчитать из XP; сделать явное объяснение.

### UX-10 · P2 · Неполная клавиатура и motion policy

**Problem:** reorder требует drag; tabs гардероба не имеют полной roving navigation; reduced motion покрывает часть quest effects. **Evidence:** `QuestCard.tsx:41`, role tabs в `ProgressPage.tsx`, `styles.css` progress width/modal rise/loading pulse и ReactFlow animated edges. **Proposed change:** операции перемещения в menu, keyboard category tabs, общий reduced variant и отсутствие декоративных loops. **Benefit:** доступность и спокойствие. **Risk:** не отключать движение/zoom дерева, необходимые для управления; отсутствие frame-rate теста не основание заявлять доказанную проблему производительности.

### UX-11 · P2 · Небольшой текст и тематическая неоднородность

**Problem:** много labels 11–12 px и одинаково обрамлённых панелей; hero остаётся отдельной navy-сценой в разных темах. **Evidence:** [theme-Текстура-1366.png](artifacts/design-phase1/theme-Текстура-1366.png), [theme-Ночное небо-1366.png](artifacts/design-phase1/theme-Ночное%20небо-1366.png), текущий CSS hardcoded hero colors. **Proposed change:** использовать действующие semantic theme aliases, ясные роли 14–17 px для рабочего текста, минимум frames. **Benefit:** лучше читабельность и целостность. **Risk:** пользовательский цвет навыка может иметь плохой контраст; текст должен оставаться нейтральным, цвет использовать в маркере.

### UX-12 · P2 · Неочевидный объём существующих achievements/stats

**Problem:** UI-копия может обещать значки и статистику шире активного интерфейса. **Evidence:** `LevelRewards.tsx:53` LevelBadges не импортируется экраном; ProgressPage не рендерит графики, несмотря на старые classes/recharts dependency. **Proposed change:** сначала ясно показать существующие уровневые вехи и top skills; новые achievements/charts выделять отдельным решением. **Benefit:** дизайн соответствует реально сохранённым данным. **Risk:** accidental feature creep и новый migration schema.

## Global system audit и specialist passes

ydn-web-design и его профиль прочитаны полностью. Он определяет authority, кириллицу, quality, reuse, content-driven responsive, состояния, motion justification, anti-slop и visual verification. Отдельного опубликованного token package/component API он не предоставляет. Локальная реализация использует существующие CSS-токены и Ui.tsx. Сравнение global/local — DESIGN.md §1; существующие ocean studio/manrope samples не объявлены универсальными.

Taste применён в режиме redesign с сохранением основы: извлечены существующая палитра, font, logo, IA; структура Home изменена по evidence. Его рекомендации для маркетинговых сайтов не переносятся на рабочий RPG-экран.

Impeccable context проверен, режим Operate согласуется с ежедневной работой. Detector исходного `src` — [current-detector.json](artifacts/design-phase1/current-detector.json); его предупреждения — подсказки, не доказательство дефекта каждого border. Например accent выбранного пункта/ветки может иметь функцию; dormant CSS не равен активному UI. Результат Golden — [golden-detector.json](artifacts/design-phase1/golden-detector.json).

React best practices: существующий Vite/React stack и lazy pages сохраняются, новых dependencies нет. Prototype импортирует pure model functions и существующие presentation components, не подключает StoreProvider или Electron IPC. С версии 5 только ID-порядок макета записывается в отдельный localStorage namespace; AppState туда не сохраняется.

Для дополнительного accessibility pass использованы [актуальные Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). Замечания по файлам:

- `src/components/Ui.tsx:4` — progress без доступного значения.
- `src/components/Ui.tsx:14` — shared dialog без общего focus trap/restore/inert.
- `src/components/QuestCard.tsx:41` — drag handle без альтернативы клавиатурой.
- `src/pages/QuestsPage.tsx:112` — поиск и фильтр не имеют полноценного accessible name; placeholder/icon недостаточны.
- `src/styles.css:62` — fixed minimum + hidden overflow в узком renderer.
- `src/styles.css:730` — loading loop требует reduced-motion и доступного status.

Рекомендации URL state, Title Case и веб-навигации не вводят новый router и английскую типографику в локальную русскую desktop app. Scope и PRODUCT имеют приоритет.

## Итог первого этапа

Работающий продуктовый каркас сохраняется. Наибольшую пользу дают заметность цели/квеста/баланса, привычные действия списка, достоверность гардероба и единая доступность primitives. Версии 4–5 добавили отдельный фокус, простой недельный цикл и точную перестановку; версия 6 уточнила парные отметки слева и конечные навыки под героем справа, текущая версия 7 расширяет рамки и улучшает отступы/hover. Полная functional parity соседних страниц, сохранение недельных задач и все темы — задачи интеграции. Пользовательская проверка новой композиции и быстрого понимания ещё предстоит.
